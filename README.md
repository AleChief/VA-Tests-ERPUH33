# VA-Tests-ERPUH33
Сценарии автоматизированного тестирования для конфигурации 1С:ERP.Управление холдингом 3.3

## Ветка erpuh-file-base-env

Не для вливания. Это `erpuh-3.3.5.1-fixes` плюс условия выполнения: файловая база, лицензия для
разработчиков, все разделы подряд в одной базе. Добавлены ожидания, повторы и проверки собственного ввода; проверки
сценариев не ослаблены, кроме маски в эталоне 05.05 (ниже).

- Подключение тестового клиента обёрнуто в `Попытка ... Исключение / И Пауза 30 / повторное подключение`: при
  медленном старте клиента первая попытка не успевает.
- Маски заголовков окон `' *'` заменены на `' **'` (замечание проверки синтаксиса VA, нужно для запуска через MCP;
  пакетный запуск работает и без них). По той же причине в `0_ЭкспортныеСценарии` закомментированы пустые ветки
  `Если ... Тогда` без шагов в теле. Заголовки групп `* ...` закомментированы (`// * ...`), больше всего в
  `1_НСИ\02`; шаги не менялись, поведение то же.
- Лицензия для разработчиков ограничивает число одновременных клиентов: фичи `6_Закупки` закрывают профили, которые
  им не нужны, а `3_Бюджетирование` после закрытия клиента ждёт 60 секунд и подключается повторно. Перед 20.09,
  который переключает пользователей, `3_Бюджетирование\19а` выключает у них вопрос «Завершить работу с программой?»:
  VA на него не отвечает и завершает клиента, а сеанс такого клиента в файловой базе продолжает занимать место.
- Паузы и явный переход к строке или колонке там, где форма под нагрузкой не успевала: резервы в
  `4_Планирование\02` (02.06), список договоров перед поиском по шаблону; проверка собственного ввода с повтором
  («Результат работы комиссии»): серверный контроль формы под нагрузкой затирал поле.
- Все разделы идут в одной базе (у вендора `6_Закупки` — на отдельной базе):
  - фоновое обновление доступа на уровне записей (после настроек `1_НСИ\01` и после создания пользователей в 02.01)
    в файловой базе блокирует таблицы целиком: `1_НСИ\01а` (01а.02) и `1_НСИ\02` перед 02.03 ждут его конца, иначе
    запись организаций падает с «Конфликт блокировок»;
  - `4_Планирование\01` включает обязательность статей бюджетов, поэтому `5_Казначейство` и `6_Закупки` заполняют
    статьи БДДС и БДР в договорах и в 05.02, а `5_Казначейство\00` задаёт статьи по умолчанию для операций графиков
    финансовых инструментов;
  - номенклатура и приказы комиссии уже созданы `1_НСИ`: единица Товар2 «Упак», приказ комиссии №2;
  - тегом `@ERPUH33_dup` помечены 28 сценариев `6_Закупки\02`, повторяющих `1_НСИ\02`; в общей базе их пропускаем
    параметром запуска VA `ignoretags`.
- `1_НСИ\08` выравнивает часовой пояс программы с поясом сервера 1С, если они разные: иначе записанный документ
  остаётся «Черновиком» с периодом на час позже, и ввод на основании в `4_Планирование\04` запрещён. Пояс меняется
  только в монопольном режиме, поэтому фича идёт отдельно, перед `4_Планирование`.
- 05.05: в эталоне `ВА_ЗаполнениеИзРН_Движения_1.mxl` пятый знак после запятой в трёх ячейках заменён маской `*`
  (215 126,9181\*, 46 386,7417\*, 98 823,9280\*): на файловой базе он расходится (вопрос вендору — 1C-CPM/VA-Tests-ERPUH33#1, п. 2).
- Сценарии, которые закомментированы в исходном наборе (`6_Закупки`: файлы 06, 08–11 целиком и 05.11 «Договор ДД2 /
  ПТУ ДД2»; `5_Казначейство`: «Структура сценария 2.7 Платежи наличные»), здесь раскомментированы и проходят.
- `2_Дымовые_3.3.5.1` — набор дымовых тестов для 3.3.5.1: генератор VA на всю конфигурацию, исключения в
  `ОбъектыИсключения` (вендорские и найденные прогоном). 9104 сценария.

Проверено на ERP УХ 3.3.5.1, платформе 8.3.27.2214 и Vanessa Automation 1.2.043.47, файловая база: сценарные —
сплошной цепочкой от пустой базы; дымовые — без падений.
